# OctoAcme Project Management Docs

This folder contains the core project management guidance used by OctoAcme for planning, delivery, and continuous improvement.

## Overview

OctoAcme runs projects through a clear lifecycle: initiation, planning, execution, release, and retrospective. In the initiation phase, the team validates the business need, defines the stakeholder list, identifies success metrics, and decides whether to move forward with planning. Once approved, planning turns the idea into a backlog, release plan, and milestone map with clear ownership, dependencies, and acceptance criteria.

During execution, the team focuses on iterative delivery, daily visibility, risk tracking, and regular reviews. The project manager coordinates schedules and communication, while product leadership clarifies priorities and success measures. Developers build and test work, QA validates quality and acceptance criteria, and stakeholders help review progress and decisions. A central set of artifacts—including the project one-pager, backlog, risk register, roadmap, and acceptance criteria—keeps work aligned and transparent.

Communication is a core project discipline. OctoAcme recommends weekly PM + product syncs, twice-weekly team standups, monthly stakeholder updates, and ad hoc escalation for risks or blockers. Escalation follows a structured path from the team to the PM, Product Lead, and sponsor when issues have broader business impact. Risks and dependencies should be tracked in a shared register and updated in regular project reviews so they can be addressed before they become delivery blockers.

Quality assurance is embedded throughout the project lifecycle. Teams are expected to write unit and integration tests, validate user-facing flows with smoke tests, run CI checks including linting and security scanning, and require review and approval before merging pull requests. Release work includes pre-deployment validation, staging checks, production verification, rollback planning, and release communication. After each milestone or release, OctoAcme recommends a retrospective to capture lessons learned and convert them into actionable improvements.
